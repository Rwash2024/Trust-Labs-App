# تحديث بيانات المنافسين في مركز الحملات

مركز الحملات بيحذّر لما بيانات المنافسين تعدّي 14 يوم (وبيقول «حدّثها» بعد 30). التحديث بيتعمل كده:

## الطريقة السريعة
1. من تاب **المنافسين** دوس **«نسخ طلب التحديث»** وابعته لـ Claude، أو قول له: «حدّث بيانات المنافسين في مركز الحملات».
2. Claude بيسحب البوستات من مزوّد البيانات (Alexandria / scrapecreators)، ويحفظها خام في مجلد مؤقت، ويشغّل السكربت، ويراجع الفرق معاك قبل ما يعمل commit.

## اللي بيتسحب
- **انستجرام:** آخر 72 بوست لكل حساب (6 صفحات تقريبًا).
- **فيسبوك:** 6 لـ 9 بوستات لكل صفحة (المصدر بيدّي 3 بوستات في الصفحة).
- الحسابات والصفحات من `src/data/competitors.json` (حقلي `instagram` و`facebook`).
- التكلفة: حوالي 1 لـ 2 كريدت Firecrawl للنداء، يعني تقريبًا 60 لـ 70 نداء للتحديث الكامل. لو الرصيد قليل حدّث انستجرام بس أو الأكبر 3 منافسين.

## السكربت (لو عايز تشغّله بنفسك)
```bash
cd campaign-dashboard
node scripts/refresh-competitors.mjs <مجلد-الخام> 2026-12-20 --dry   # يوريك الفرق بس
node scripts/refresh-competitors.mjs <مجلد-الخام> 2026-12-20         # يكتب competitors.json
```
المجلد فيه ملف لكل منافس ومنصة: `المختبر.ig.json` و`المختبر.fb.json` (الاسم زي ما هو في competitors.json بالظبط).

## اللي بيتغيّر واللي لأ
- **بيتغيّر:** الأرقام (متوسط اللايكات والتفاعل، مشاهدات الريلز، أحسن أيام وساعات النشر) وتاريخ السحب.
- **ما بيتغيّرش:** `sample.notes` و`insights` و`dataQuality` وأسماء الحسابات. دي مكتوبة بإيد، وفيها أرقام قديمة، فراجعها بعد كل تحديث.

## بعد التحديث
شغّل `npm test` (فيه اختبار إن التاريخ صالح)، وبعدين commit وdeploy.
